# DevsTeach 13 — « Où ranger les clients ? »

**Style de voix : jeune et complice, rythme rapide, pédagogue sur les explications.**

## Voix off

```
[intrigué] Comment un site retrouve TON compte parmi des millions ?
[complice] Jeudi. Le client veut un espace membres : nom, email, commandes… pour des milliers de clients.
[amusé] Ton collègue propose : « Un gros fichier texte. Une ligne par client. »
[rapide] Soit le fichier texte. Soit une base de données.
[défi] Tu ferais quoi ?
[pause]
[explique] Une base de données, c'est un classeur Excel surpuissant. Chaque feuille est une table : une table clients, une table commandes. Chaque ligne, un client. Chaque colonne, une info.
[pédagogue] Chaque client a un numéro unique : son id. Dans la table commandes, tu notes l'id du client. Une commande sait toujours à qui elle appartient.
[malin] Pour lui parler, on utilise SQL : SELECT étoile FROM clients WHERE email égal telle adresse. Et en un éclair, le bon client sort parmi des milliers.
[conseil] Avec PHP, le duo classique, c'est MySQL.
[sérieux] Le fichier texte devient lent, se corrompt, et deux inscriptions en même temps peuvent s'écraser.
[amusé] Le collègue a supprimé son fichier. Discrètement.
[teaser] Demain : quelqu'un a piraté le site.
```

**Choix :** 🟢 Un gros fichier texte / 🔴 Une base de données (bonne réponse : 🔴, afficher les tables clients et commandes reliées par l'id, et une requête SELECT)

**Bandeau :** JEUDI • 10:40 / Bureau – Startup / Toi, stagiaire dev

**Hook :** 10 000 clients à ranger… et mon collègue propose un fichier texte 📄

**Légende :** Tables, lignes, colonnes, id : la base de données expliquée simplement 👇
