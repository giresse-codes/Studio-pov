# DevsTeach 14 — « Le site s'est fait pirater »

**Style de voix : jeune et complice, rythme rapide, pédagogue sur les explications.**

## Voix off

```
[tendu] Un pirate est entré dans le site… en tapant dans le champ email.
[complice] Lundi, 7 h. Max : « Il a vu les emails de tous les clients ! »
[explique] Ton PHP colle ce que tape le visiteur directement dans la requête SQL. Le pirate a écrit du code SQL à la place d'un email, et il a détourné la requête. Ça s'appelle une injection SQL. Pire : les mots de passe sont stockés en clair.
[rapide] Soit tu bloques les mots dangereux, comme SELECT ou DROP. Soit tu passes aux requêtes préparées, et tu hashes les mots de passe.
[défi] Tu ferais quoi ?
[pause]
[explique] Bloquer des mots, c'est perdu d'avance : les pirates connaissent cent façons de les écrire autrement.
[pédagogue] Une requête préparée, c'est un formulaire avec des cases. Tu envoies la requête avec un point d'interrogation à la place de l'email, puis l'email à part. La base le traite toujours comme du texte, jamais comme du code. En PHP, avec PDO : prepare, puis execute.
[sérieux] Et les mots de passe : password_hash les transforme en charabia impossible à inverser. Pour vérifier : password_verify.
[soulagé] Faille fermée. Si un pirate revient, il ne trouvera que du charabia.
[teaser] Demain, dernier épisode : Max découvre l'intelligence artificielle.
```

**Choix :** 🟢 Bloquer les mots dangereux / 🔴 Requêtes préparées + hash (bonne réponse : 🔴, afficher `prepare("… WHERE email = ?")`, `execute([$email])`, `password_hash` / `password_verify`)

**Bandeau :** LUNDI • 07:00 / Bureau – Startup / Toi, stagiaire dev

**Hook :** Deux mots de code qui bloquent la faille la plus célèbre du web 🛡️

**Légende :** Requêtes préparées et mots de passe hashés : la base de la sécurité. Partage à un dev 👇
