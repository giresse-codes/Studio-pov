# DevsTeach 11 — « Mettre le site en ligne »

**Style de voix : jeune et complice, rythme rapide, pédagogue sur les explications.**

## Voix off

```
[gêné] J'ai envoyé le lien du site au client… et c'était mon disque dur.
[complice] Mardi. Le site est fini. Tu envoies l'adresse : C, deux points, Bureau, index point html. Le client clique : évidemment, rien.
[explique] Ce fichier est sur TON ordinateur. Pour que tout le monde voie un site, il doit vivre sur un serveur : un ordinateur allumé jour et nuit, connecté à Internet.
[rapide] Soit tu laisses ton ordinateur allumé en permanence. Soit tu passes par un hébergeur.
[défi] Tu ferais quoi ?
[pause]
[explique] Ton ordinateur ? Une coupure de courant, une mise à jour, et le site disparaît.
[pédagogue] Un hébergeur loue une place sur ses serveurs. Pour un site en HTML, CSS et JavaScript, il existe même des solutions gratuites, comme GitHub Pages ou Netlify.
[malin] Ton site est déjà sur GitHub ? Tu actives Pages dans les réglages, et en une minute, tu as une vraie adresse.
[conseil] Ensuite, un nom de domaine, du genre client point com : environ dix euros par an.
[amusé] Le client a déjà montré le site à sa mère, sa voisine, et au chauffeur de taxi.
[teaser] Demain : le formulaire doit envoyer de vrais emails.
```

**Choix :** 🟢 Mon ordinateur allumé / 🔴 Un hébergeur (bonne réponse : 🔴, afficher ordinateur → GitHub → GitHub Pages → nom de domaine)

**Bandeau :** MARDI • 17:30 / Bureau – Startup / Toi, stagiaire dev

**Hook :** Mettre ton site en ligne gratuitement en 1 minute 🌍

**Légende :** Serveur, hébergeur, nom de domaine : enfin expliqué simplement 👇
