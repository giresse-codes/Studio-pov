# DevsTeach 12 — « Le formulaire doit envoyer des mails »

**Style de voix : jeune et complice, rythme rapide, pédagogue sur les explications.**

## Voix off

```
[sérieux] Ne mets JAMAIS ton mot de passe dans ce fichier.
[complice] Mercredi. Le client ne reçoit aucun message du formulaire. Ils disparaissent.
[explique] HTML, CSS, JavaScript tournent dans le navigateur du visiteur. Pour envoyer un email, il faut un programme sur le serveur.
[hésitant] Un collègue propose : « Mets le mot de passe de la boîte mail dans le JavaScript. »
[rapide] Soit tu le suis. Soit tu écris un petit script PHP sur le serveur.
[défi] Tu ferais quoi ?
[pause]
[sérieux] Le JavaScript, tout le monde peut le lire : clic droit, afficher le code… et voilà ton mot de passe.
[explique] Le PHP, lui, reste caché sur le serveur. Le visiteur ne voit que le résultat.
[pédagogue] Dans le formulaire : action égal contact point php, method égal post. Dans contact point php : tu récupères les champs avec dollar underscore POST, tu les vérifies encore, et tu envoies l'email.
[malin] Les vérifications HTML se contournent. Celles du serveur, non. Ce sont elles qui comptent.
[conseil] GitHub Pages ne fait pas tourner le PHP : il te faut un hébergeur qui l'accepte.
[satisfait] Dix secondes plus tard, le téléphone du client sonne. Un email.
[teaser] Demain : où ranger les infos de milliers de clients ?
```

**Choix :** 🟢 Le mot de passe dans le JavaScript / 🔴 Un script PHP (bonne réponse : 🔴, afficher navigateur → serveur PHP → email, et `action="contact.php" method="post"`)

**Bandeau :** MERCREDI • 13:15 / Bureau – Startup / Toi, stagiaire dev

**Hook :** Ce que le visiteur voit… et ce qu'il ne doit jamais voir 🔐

**Légende :** Front et back enfin expliqués avec un vrai exemple. Enregistre 👇
