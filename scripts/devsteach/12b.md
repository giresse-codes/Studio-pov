# DevsTeach 12b — « Le formulaire doit envoyer des mails » (la réponse)

```
[sérieux] Si tu as suivi ton collègue… n'importe qui pouvait faire clic droit, afficher le code, et lire le mot de passe de la boîte mail. Grosse erreur.
[complice] La réponse : PHP, côté serveur.
[explique] Le code JavaScript, le visiteur le voit. Le code PHP, lui, reste caché sur le serveur. Le visiteur ne voit que le résultat.
[pédagogue] Dans ton formulaire, tu écris action égal contact point php, et method égal post. Dans contact point php, tu récupères les champs avec dollar underscore POST, tu vérifies à nouveau qu'ils sont valides… et tu envoies l'email.
[malin] Tu te souviens ? Les vérifications HTML, on peut les contourner. Celles du serveur, non. C'est elles qui comptent vraiment.
[conseil] Attention : GitHub Pages ne fait pas tourner le PHP. Il te faut un hébergeur qui accepte PHP.
[satisfait] Tu testes. Dix secondes plus tard, le téléphone du client sonne. Un email.
[teaser] Prochain épisode : où ranger les infos de tous les clients ?
```

**Bonne réponse :** 🔴 Un script PHP — afficher le schéma navigateur → serveur PHP → email, et action="contact.php" method="post"

**Hook :** Ne mets JAMAIS ton mot de passe dans ce fichier 🔐

**Légende :** Ce que le visiteur voit, ce qu'il ne voit pas : la différence entre le front et le back. Enregistre 👇
